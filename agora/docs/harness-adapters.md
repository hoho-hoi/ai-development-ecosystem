# ハーネスアダプタの要件

## 0. この文書の範囲

**アダプタ**は、agora とハーネスの間に入り、モジュールからセッションを作るものです。
既存の ACP アダプタ（pi-acp など）を使う場合も、SDK で自作する場合も、agora 側の設定作成を含めて一つのアダプタとみなします。

この文書は、**どのハーネスのアダプタにも求める要件**を定めます。
個々のハーネスでどう実現するかは定めません（実装はコードとテストにあります）。
新しいハーネスを足すときは、ここに挙げた要件をすべて満たすか、満たせない要件を明記して合意を取ります。

## 1. 用語

- **モジュールの内容**：指示、skill、モジュールの MCP サーバー、`plugin.json` の起動条件（model、tools、builtinTools など）。
- **agora のツール**：agora のブリッジが提供するツール（send、receive など）のうち、モジュールの `tools` で許したもの。
- **最初のリクエスト**：セッションの会話で、ハーネスが LLM に送る 1 回目のリクエスト。

## 2. 要件

### A. エージェントの中身

- **A1 指示**：モジュールの指示が、最初のリクエストから指示として入っていること。
  指示として入るのは、ハーネス自身の基本の指示とモジュールの指示だけ。それ以外（ホーム・作業場所・その親ディレクトリにある指示ファイルなど）は入らない。
- **A2 skill**：モジュールの skill がすべて、最初のリクエストから一覧としてモデルに見えること。それ以外の skill は見えない。
- **A3 ツール**：モデルが使えるツールは次の 3 種類だけ。いずれも最初のリクエストで、呼べるツールとして宣言されていること。
  - 組み込みツール（`builtinTools: true` のときだけ）
  - agora のツール
  - モジュールの MCP サーバーのツール

  検索してから見つける形（遅延読み込み、スクリプト経由の呼び出し）にはしない。ハーネスが自動で足すツールやサブエージェントは無効にする。
- **A4 権限**：承認待ちで止まらないこと。させたくないことは、ツールを渡さないことで防ぐ。

### B. モデルと接続

- **B1 モデル**：モジュールの `model` で動くこと。アダプタは、今どのモデルで動いているかを agora に報告できること。指定どおりにできないときは、起動を失敗させる。
- **B2 接続先**：LLM へは agora が渡した接続先（LiteLLM）と鍵だけで接続すること。ハーネス自身のログインやサブスクの認証は使わない。
- **B3 鍵**：鍵はファイルに書かずに渡すこと。書くしかないときは、そのファイルを記録の回収から除く。

### C. 隔離と再現性

- **C1 外の設定を読まない**：ホームや作業場所にある、ハーネス用の設定・認証情報・拡張・記録を読まないこと。ハーネスの状態の置き場所はすべてセッション専用にする。
- **C2 勝手に通信しない**：LLM の接続先とモジュールの MCP サーバー以外へ、自動で通信しないこと。更新確認、モデル一覧の取得、統計の送信、パッケージの導入などは止める。
- **C3 機能を足さない**：モジュールに書かれていない振る舞いを足さないこと。ハーネス独自の便利機能（キャッシュの維持、自動の追加ツールなど）は、既定で有効なら切る。必要になったら、合意してから起動条件の項目にする。
- **C4 版の固定**：ハーネスの振る舞いを変えるものの版は、すべて固定されて記録に残ること。ハーネス本体、アダプタ、SDK がこれにあたる。モジュールには、ハーネスの版だけを書けば済むようにする。

### D. 会話と記録

- **D1 会話の単位**：`per_message` では、メッセージごとに新しい会話を始められること。`persistent` では、会話を続けられること。
- **D2 再開**：会話の記録から会話を再開できること（clone に必要）。できないハーネスでは、clone を明示的に失敗させる。
- **D3 記録**：ハーネスの会話記録は、セッション専用の場所に残り、終了時に回収できること。
- **D4 経過の報告**：次のものを agora に逐次伝えること。
  - モデルの返答
  - ツール呼び出し（名前、引数、結果）
  - 使用量

### E. 失敗の仕方

- **E1 黙って変えない**：モジュールの内容のうち、写せないものが 1 つでもあれば、起動を失敗させること。黙って無視したり、代わりのもので動かしたりしない。

## 3. agora との約束（ACP）

agora とアダプタは ACP で話します。アダプタは少なくとも次のメッセージに応えます。

- `initialize`
- `session/new`：MCP サーバーの一覧を受け取る。今のモデルを報告する
- `session/prompt`
- `session/update`：返答、ツール呼び出し、使用量を送る
- `session/set_config_option`：モデルの切り替え
- `session/load`：再開。D2 を満たす場合

## 4. 確かめ方

要件は、ハーネスと版の組ごとに確かめます。いま自動テストで確かめているのは、設定の生成（A〜C の一部）だけです。

最初のリクエストの中身（A1〜A3）と、外への通信（C2）を実物で確かめる適合テストは、まだありません（未決）。
