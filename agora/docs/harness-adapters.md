# ハーネスアダプタの要件

## 0. この文書の範囲

**アダプタ**は、agora とハーネスの間に入り、モジュールからセッションを作るものです。
ハーネスの SDK で自作したもの（pi の `images/pi/agora-pi.mjs` など）も、既存の ACP アダプタも、agora 側の設定作成も含めて、一つのアダプタとみなします。

この文書は、**どのハーネスのアダプタにも求める要件**を定めます。
要件は、アダプタがどう作られているか（どのファイルを読まないか、など）ではなく、**モデルに何が渡り、何が起きるか**で書きます。
判定には、LLM の手前にいるゲートウェイ（LiteLLM）の記録を使います。ハーネスの自己申告には頼りません。

新しいハーネスを足すときは、すべての要件を満たすか、満たせない要件を明記して合意を取ります。

### 隔離の目的
モデルの文脈に入るものを、**ハーネスとモジュールと依頼だけ**にするためです。
そうすれば同じモジュールは同じものとして動き、再現でき、ハーネスを替えられます。
コンテナで動かすのは別の目的のためで、ツール（シェルなど）がホストや鍵に触れないようにするためです。これは agora の実行の仕組みの責任で、アダプタの要件ではありません。

## 1. 用語

- **モジュールの内容**：指示、skill、モジュールの MCP サーバー、`plugin.json` の起動条件（model、tools、builtinTools など）。
- **agora のツール**：agora のブリッジが提供するツール（send、receive など）のうち、モジュールの `tools` で許したもの。
- **リクエスト**：ハーネスが LLM に送る 1 回分の呼び出し。LiteLLM に本文ごと残る。
- **見えるツール**：リクエストのツール一覧のうち、モデルが呼べるもの（遅延読み込みの印が付いて見えないものは数えない）。

## 2. 要件

### A. モデルに渡るもの（各会話の最初のリクエストで判定）

- **A1 指示**：指示に入っているのは、ハーネス自身の基本の指示と、モジュールの指示だけ。
  基本の指示はハーネスの版で決まり、モジュールや作業場所によって変わらない。
- **A2 skill**：モジュールの skill がすべて一覧として入っている。ほかの skill は入っていない。
- **A3 ツール**：見えるツールは次の 3 種類だけで、最初のリクエストから揃っている。
  - 組み込みツール（`builtinTools: true` のときだけ）
  - agora のツール
  - モジュールの MCP サーバーのツール
- **A4 モデル**：リクエストのモデルが、モジュールの `model` と一致する。
- **A5 会話**：会話の内容は、依頼（agora が送ったメッセージ）と、その会話でのモデルの返答・ツールの結果だけ。

### B. 動き方

- **B1 止まらない**：承認待ちなどで止まらない。させたくないことは、ツールを渡さないことで防ぐ。
- **B2 接続先**：LLM へのリクエストは、すべて agora が渡した接続先と鍵を通る。ほかの経路（ハーネス自身のログインなど）で LLM を呼ばない。
- **B3 鍵が漏れない**：鍵は、モデルに渡るもの（A）にも、ツールが触れる場所（環境変数・ファイル）にも現れない。
- **B4 会話の単位**：`per_message` では、メッセージごとに新しい会話になる（A5 で判定）。`persistent` では、会話が続く。
- **B5 黙って変えない**：モジュールの内容のうち写せないものがあれば、起動を失敗させる。違うモデルで動き始めたときも同じ。

### C. agora との約束

アダプタは agora と ACP で話し、少なくとも次のメッセージに応えます。

- `initialize`
- `session/new`：MCP サーバーの一覧を受け取る。今のモデルを報告する
- `session/prompt`：返答の終わりを返す。`_meta.traceparent` があれば、そのターンの LLM へのリクエストすべてに `traceparent` ヘッダーとして付ける（LLM の呼び出しが agora のターンの下に入る）
- `session/update`：返答の文章を送る
- `session/cancel`、`session/close`
- `session/set_config_option`：モデル

記録（会話の全文、ツール呼び出し、使用量、費用、実際に使われたモデル）は LiteLLM から取るので、アダプタには求めません。

### D. 版

- **D1 固定**：振る舞いを変えるもの（ハーネス本体、アダプタ、SDK）の版は、イメージで固定され、イメージ ID が毎回記録される。モジュールにはハーネスの版だけを書けば済む。

## 3. 確かめ方

ハーネスと版の組ごとに、モジュールを 1 つ動かします。そのうえで LiteLLM の記録を見て、各会話の最初のリクエストで A1〜A5 を確かめます。
B は、agora の記録（モデルの確認、セッションの状態）と LiteLLM の記録を合わせて確かめます。

この確認を自動で行う仕組みは、まだありません（未決）。
